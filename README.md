# Frontier Terrain Studio

Frontier is a browser-based terrain editor built around **independent sparse signed-distance fields**, not heightmaps. Each island owns its continental field, volumetric chunks, layers, history, visibility, and bake state. The editor combines an unbounded 2D island SDF workflow with direct volumetric sculpting and marching-cubes rendering. Built with React, TypeScript, Three.js, and Vite.

## Run

```bash
npm install
npm run dev
```

The development server binds to `0.0.0.0:5173`.

```bash
npm run build
npm run preview
```

## Independent islands

- The **Island SDFs** panel selects, focuses, hides, and shows islands without merging their fields.
- **New independent island** creates an empty field at the current world center and opens Shape mode.
- Aurelia, Sable Isle, East Key, South Atoll, and Far Shoal are separate default island fields.
- Shape strokes and Sculpt raycasts affect only the active island. Hidden or locked islands reject edits.
- Layers, custom sculpt layers, undo/redo history, allocated volumes, and baking are scoped to the active island.
- The ocean combines visible island SDFs for water shading; it does not merge their editable volumes.

## 1. Shape — unbounded island SDF

- Draw the selected island with **Add land**, **Subtract**, and **Smooth**.
- Positive field values represent land; negative values represent ocean.
- The 2D field is stored in sparse **65 × 65 Float32 chunks**, each covering **2.048 km**.
- Pan with right mouse, middle mouse, Alt + drag, or Space + drag. There is no fixed map rectangle.
- Zoom around the cursor from regional scale down to individual stroke detail.
- Untouched preview chunks can be pruned; edited continental chunks remain in the sparse project.
- **File → New blank world** starts with an unbounded ocean. A single Add stamp creates land immediately.

### Eroded strokes

The **Stroke erosion** slider controls natural coastline breakup:

1. Absolute-coordinate domain warping bends the stamp before the SDF operation.
2. Multiscale noise breaks the edge into bays and peninsulas.
3. Ridged channels cut smaller erosion features into the stroke.
4. Smooth union or subtraction combines the result with the continental field.

The noise is sampled in absolute world coordinates, so adjacent chunks evaluate the same edge without visible seams. Set erosion to zero for clean circular stamps or increase it for heavily fractured coastlines.

## 2. Sculpt — Landscape-style volumetric tools

The 3D editor does **not** write heightmap samples and does not derive density from `height − y`. Each resident chunk owns a **24 × 24 × 24 Float32 density volume** with a positive-solid convention, generated by direct 3D CSG and noise:

1. The coastline SDF from the Shape stage is intersected with a rounded continental crust volume, so the crust thins with depth instead of being extruded from a height column.
2. Closed, domain-warped 3D ellipsoids are smooth-unioned into that crust to build mountain solids in all three axes.
3. 3D erosion noise displaces the volume in X, Y, and Z along the coast rather than perturbing a surface height.
4. Authored cave and arch volumes are carved last, after erosion, so noise cannot refill them. These cavities are unreachable by any heightfield representation.

The brush set follows Unreal's Landscape tool model — a tool is a mode with a two-point gesture, not a one-shot stamp:

| Tool | Key | Behaviour |
| --- | --- | --- |
| Sculpt | `R` | Smooth union with a spherical density stamp. Hold **Shift** to subtract instead and carve into rock. |
| Smooth | `S` | Averages neighboring 3D density samples. Reads from an immutable source copy, so repeated passes converge instead of feeding back on themselves. |
| Flatten | `F` | Blends density toward the plane sampled at the first hit point, with adjustable falloff. |
| Ramp | `G` | Two-point gesture: press at the start, drag to the end, release to commit. A live guide shows the segment; the guide disappears on release, and only the release writes density. |
| Erosion | `E` | Thermal/hydraulic-style relaxation of the 3D field, tightening slopes and cutting channels. |
| Noise | `N` | Adds band-limited 3D noise to the field, with strength controlling amplitude. |

Shared behaviour:

- Radius, strength, and falloff brushes apply to every tool; the radius slider is the same value the engine raycasts against.
- X/Z symmetry mirrors the stroke about the island's own content center, not the world origin.
- Cursor hit-testing uses a per-chunk BVH (`three-mesh-bvh`, `indirect: true`, refit when the vertex count is unchanged) instead of brute-force triangle scans.
- Additional sculpt layers store independent sparse density residuals; layer visibility and opacity recombine residuals without discarding them.
- Lit, Clay, and Wireframe modes all render the extracted isosurface, not a heightfield grid.

### Marching-cubes renderer

- Each visible island uses a **7 × 7 camera-following search window**, clipped to that island's actual content bounds. The total mesh count is not hard-coded to 49.
- Marching cubes extracts each chunk's zero-density isosurface. Composite `islandId:cx,cz` keys prevent cross-island mesh or cache collisions.
- Chunks whose field is entirely solid or entirely empty are rejected before they ever become scene objects, which removes the interior chunks under a landmass as well as the open ocean around it. The default Aurelia scene resolves **36 renderable chunks** out of 49 candidates.
- Chunk geometry is allocated for **4096 triangles** rather than the library default of 8000; the largest resident chunk needs about 2.1k, so this halves per-chunk buffer memory without clipping real geometry.
- Shared absolute-coordinate sampling and overlapping field samples keep chunk edges aligned.
- Only affected chunks are remeshed after a sculpt stroke or undo/redo. Remeshing is additionally capped at **four chunks per animation frame**, so a large brush cannot stall a frame; hiding one island does not regenerate another.
- Unedited chunks can be evicted when they leave the resident set. Edited/baked chunks expand bounds when necessary so boundary strokes remain resident.
- The brush is a depth-tested 3D wire sphere at the actual ray hit, not a surface-projected line across ocean or sky.
- Terrain and clay use diffuse **Lambert** shading rather than full PBR: the landscape is matte, so the roughness/metalness evaluation was pure per-fragment cost.
- The atmospheric background is a gradient-and-sun-glow sphere instead of the physical scattering model, which spent dozens of transmittance samples per pixel on a smooth blue gradient.

### Frame cost and adaptive resolution

Measured in the headless test harness (Chromium + SwiftShader, 1600 × 1000 window, 591 × 474 drawing buffer):

| Stage | Ocean on | Ocean off |
| --- | --- | --- |
| Baseline (before this pass) | 1 FPS / ~833 ms | 2 FPS / ~585 ms |
| After volumetric generation fix | 5 FPS / 216 ms | 6 FPS / 181 ms |
| After sky, material, ocean-noise and resolution work | **10 FPS / 101 ms** | **13 FPS / 76 ms** |

Where the frame time actually goes, all measured rather than assumed:

- **CPU submission is 0.4 ms per frame.** `renderer.render()` returns almost immediately; 38 draw calls and 45k rendered triangles are not a main-thread cost. The 97.9% "idle main thread" profile from the baseline is the same finding: the CPU is waiting, not working.
- **Idle chunk streaming does nothing.** Residency only updates when the camera crosses a chunk boundary; there is no per-frame remeshing when the user is not sculpting.
- **Frame time scales with drawing-buffer pixels.** At fixed geometry and draw calls: 280k px → 119 ms, 136k px → 66 ms, 82k px → 51 ms, 69k px → 44 ms. Roughly 0.36 µs per pixel, which is fill cost in a software rasterizer.
- **The test environment is CPU rasterizing.** A blank page holds 60 FPS and a trivial WebGL clear holds 60 FPS, but adding 2M `Math.sin` calls per frame in JavaScript drops the same page to 19 FPS — this sandbox's CPU is roughly 5–10× slower than a normal client CPU. That is a property of headless SwiftShader, not of the scene description; the same 45k triangles and 38 draw calls are a small load for real hardware.
- **Ocean shading was the largest single shader cost inside the app's control**, so it was reduced: one texture fetch now feeds two decorrelated wave channels instead of three fetches, the specular lobe uses repeated squaring instead of `pow(x, 420.0)` and `pow(x, 48.0)`, one `length()` serves both the view vector and fog, and foam/detail fade with distance so grazing-angle water stops aliasing into contour rings. Measured ocean cost in the same session fell from **43 ms to 25 ms** per frame at 280k px.

`preferredRenderScale` starts at `min(devicePixelRatio, 1.25)` and the engine steps the drawing buffer down to **0.55** under sustained load (and back up when frames are fast). Terrain silhouette quality is unaffected because geometry is not simplified — only the shading resolution adapts. The React UI always renders at native resolution.

## Unbounded navigation and floating origin

Horizontal movement is not limited to the original island or a fixed 16 km map. Both Shape and Sculpt preserve the same absolute world center when switching modes.

The 3D renderer periodically recenters local camera and mesh coordinates while retaining absolute chunk coordinates. This **floating origin** avoids the precision jitter that would otherwise appear after long journeys. Ocean shading and the minimap follow the same origin.

The current vertical volume range is approximately **−1,229 m to +4,096 m**. “Unbounded” refers to horizontal travel, not unlimited vertical chunks.

## 3. Bake

Baking collapses the **active island's** visible density in its allocated chunks into persistent baked volumes:

- The extracted isosurface is preserved, and other islands' fields and layers are unchanged.
- Existing residuals are committed and new strokes create fresh residuals.
- Baked chunks survive residency eviction.
- An undo snapshot is created in the active island's independent history before baking.
- Unallocated parts of the unbounded field are not baked; newly visited chunks continue to use procedural generation.

## Continental ocean shader

The animated ocean includes multi-frequency waves, Fresnel sky reflection, sun glints, shallow-water color, and shoreline foam. Its shelf and foam shader samples the combined **visible island SDFs** around the floating origin. Wave displacement is attenuated at the shoreline, and explicit depth testing/write prevents water from drawing over terrain. The lookup extends beyond mesh residency and feathers at its edges to avoid visible region boundaries.

The water is the most aggressively cost-reduced shader in the app, because it covers the whole screen: it uses one packed 256² noise texture (three independent channels, generated once) instead of sixteen procedural hashes per pixel, a 64 × 64 plane instead of 96 × 96, a specular lobe built from repeated squaring instead of high-exponent `pow`, and distance fades on micro-detail, foam, and sparkle so distant water converges to a flat fogged colour instead of aliasing.

## Save and export

- Projects autosave to browser local storage after edits using **version 3**. Version-2 projects are migrated into one independent island.
- **Frontier project** exports every independent island: modified continental chunks, volumetric residuals, baked chunks, layers, visibility, lock state, center, and settings.
- **Sparse SDF volume** exports `frontier-independent-islands-sdf` version 3 with positive-solid Float32 density chunks, absolute coordinates, island IDs/names/visibility, chunk resolution, and vertical range.
- **Viewport** exports a clean PNG of the current 3D camera.
- **Open project** restores `.frontier.json` projects.
- No heightmap export is generated.

Local storage has browser-specific capacity limits. Export large sparse projects as files; production-scale worlds still need a disk-backed chunk service.

## Architecture

- `src/terrain/TerrainWorld.ts` — `SDFIsland` fields plus the `TerrainWorld` multi-island manager, eroded strokes, volumetric operations, independent residuals/bake/history, and v2/v3 serialization.
- `src/terrain/ViewportEngine.ts` — floating origin, bounds-clipped per-island residency, empty-chunk rejection, composite-key marching cubes, per-chunk BVH raycasting, budgeted remeshing, ramp guides, visible-island SDF ocean, adaptive render scale, stable cameras, capture.
- `src/components/ShapeCanvas.tsx` — unbounded 2D field renderer, contours, grid, pan/zoom, interpolated eroded strokes.
- `src/components/TerrainViewport.tsx` — React lifecycle bridge for the volumetric renderer.
- `src/components/MiniMap.tsx` — origin-following continental field overview.
- `src/App.tsx` — workflow, panels, project I/O, shortcuts, autosave.

## Production boundary

This is a working sparse-SDF editor foundation, not a finished Unreal-scale terrain runtime. Current volumes use a fixed vertical range and a single working marching-cubes resolution per chunk. Disk-backed streaming, background/worker meshing, hierarchical LOD (the obvious next step for frame cost, since the remaining measured expense is per-triangle and per-pixel rasterization), virtual texturing, high-resolution production export, and collaborative version control remain production extensions.
